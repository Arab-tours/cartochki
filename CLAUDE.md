# Калима (cartochki) — правила для всех сессий Claude

Сайт редактируют несколько чатов одновременно. Чтобы не затирать чужую работу:

## Перед каждой правкой
1. `git fetch origin main && git rebase origin/main` (или `git pull --rebase`) — **прямо перед** редактированием, а не в начале сессии.
2. Правьте точечно (замена конкретного фрагмента), не перезаписывайте `index.html` целиком из старой копии.
3. Сразу после правки — коммит и push. Не держите незапушенные изменения.

## Если push отклонён / конфликт
- `git fetch origin main && git rebase origin/main`, разрешите конфликт, **сохранив чужие изменения**, проверьте страницу, push снова.
- Никогда `git push --force` и никогда `git checkout --theirs/--ours` на весь `index.html`.

## Версия и «Что нового» (частый источник конфликтов)
- Номер версии — `window.APPV=N` в начале `index.html`. Поднимайте его **после** rebase: берите текущее значение из свежего `origin/main` и ставьте +1. Если при rebase конфликт именно в `APPV` — берите большее число +1.
- Запись «Что нового»: `{n:K,...}` — K = максимальный существующий `n` + 1 (считать после rebase). Новую запись — над записью с максимальным `n`.
- После правок `index.html` запускайте `python3 mkver.py` (обновляет `version.json`) и коммитьте оба файла.
- Каждое изменение сайта = подъём версии + запись «Что нового» (так хочет владелец).

## Зоны (чтобы не мешать друг другу)
- Вкладка «Уд» (тюнер, мелодии, распознавание, звук): код между `/*OUD tuner*/` и `function oudv(){`, сэмплы в `snd/`. Только аккаунт `dima`.
- `news.json` — новость дня (отдельная задача по расписанию), коммиты `news: …`.
- `worker/index.js` — Cloudflare Worker hw-check (Gemini). Изменения в нём начинают работать только после ручного деплоя владельцем — пишите об этом.
- Сборка APK/IPA: `.github/workflows/build-apps.yml` (копирует `index.html`, `sw.js`, `snd/` и т. д. в `appshell/www`).

## Проверка
- Перед push загрузите страницу в браузере (playwright) и убедитесь, что нет ошибок `pageerror`.
